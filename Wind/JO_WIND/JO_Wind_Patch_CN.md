# 《Joint Operations: Typhoon Rising》风系统与子弹风偏补丁分析报告

- **目标文件**: `jointops.exe`（32 位 PE，ImageBase `0x400000`，4,612,096 字节）
- **方法**: Ghidra 静态分析 + PowerShell 字节级扫描/补丁生成 + 游戏内实测验证
- **日期**: 2026-10-31
- **结论**: 引擎有完整的天气风系统（风速 kph、风向角度、风矢量全局），风矢量正常驱动烟雾/粒子，但 drag 函数内的风项是**死代码**（`v+=wind → v+=decel → v-=wind` 加减夹心且中间无乘法，净效果恒为零）——子弹"不受风"是 BHD 重构遗留而非缺失。通过 10 字节钩子 + `.text` 中部 cc 间隙洞注入 45 字节，子弹获得与 DFBHD 风偏补丁同款的理想恒加速风偏（`v += (wind<<2)>>K`，九档 K0–K8）。已实测生效，方向正确。

---

## 1. 地址换算约定

`.text` 内 `VA = 文件偏移 + 0x400000`。钩子位于子弹 mover `FUN_004e9d70`：VA `0x4EAA5A` = 文件偏移 `0xEAA5A`。补丁洞位于 `.text` 中部函数间 cc 对齐间隙：VA `0x7472C9` = 文件偏移 `0x3472C9`（55 × `0xCC`，尾部紧邻 `0F` 起始的下一条指令）。

## 2. 风系统取证

### 2.1 任务侧变量与生成路径

| 变量 | VA | 含义 |
|---|---|---|
| mp_wind 联机选项 | `0x02550B58` → 任务态 `0x024D20DC` | 风力设置随任务下发 |
| 模式分发 | `FUN_00524360` | 0=自定义、1=无风、2=随机风 |

模式 2 走随机风 `FUN_005dea80`；自定义路径由 MED/房主设定后经 setter 写入风矢量全局。

### 2.2 风矢量全局（核心）

| 变量 | VA | 含义 |
|---|---|---|
| wind_x | `0x02C059E4` | 16.16 定点 |
| wind_y | `0x02C059E8` | 16.16 定点 |
| wind_z | `0x02C059EC` | 恒 0（风恒水平） |
| 弱风副本 | `0x02C059F0` / `0x02C059F4` | 只写不读（死数据） |

换算在 setter `FUN_005de970(方向, 速度)` 内完成：角度 = `(90−方向)°`，幅值 `mag = 速度kph × 65536 / 234`，分量 = `sin/cos × mag >> 22`。45kph 满风分量 ≈ **197/帧**。

### 2.3 粒子侧（风"看起来只影响烟/尘"的原因）

视觉路径 `FUN_005f70c0` 读取 `0x02C059E4/E8/EC` 驱动烟雾、尘土、火苗等粒子逐帧位移——风系统本身活着且肉眼可观察，仅子弹侧断线。

## 3. 子弹侧：风为什么无效（根因）

drag 函数 `FUN_004e5ec0`（0x4E5EC0–0x4E64DE，438 条指令；4 个 mover 调用者 `0x445420` / `0x4EC920` / `0x4E9D70` / `0x545100`）内存在 BHD 重构遗留的风处理（0x4E60F3–0x4E6165，完整反汇编核实）：

```
v += wind
v += decel        ; 预计算空气阻力：decel = 表 DAT_00B7B300[速度] / drag / 0x3E，沿 -v 方向
v -= wind         ; ← 与第一句抵消，净效果恒为零
```

BHD 原版公式是 `(v + wind) * drag >> 16 - wind`——乘法夹在加减之间，风项存活；JO 重构成"预计算 decel"模型后夹心中的乘法消失，风项变死代码。**JO 中 drag≠1 只有真实空气减速、永无风偏，改 items.def 的 drag 值不可能带来风。**

两作 drag 语义完全不同：

| | BHD | JO |
|---|---|---|
| 公式 | `(v+wind)*drag>>16 − wind`（乘性阻尼） | `decel = 表[速度]/drag/0x3E`，沿 −v 方向 |
| drag=1 | 提前返回（默认弹种空转） | 正常减速 |
| drag=0 | 极端阻尼 | 零减速（除零保护） |
| drag>1 | 更快减速 | 打得更远（减速力变小） |

JO 侧防反向：`dot(v,decel)>0 → v=0`。速度字段：实例 `+0x98`=vx、`+0x9C`=vy、`+0xA0`=vz。

## 4. 补丁设计

### 4.1 代码洞选择

| 候选洞位 | 文件状态 | 运行时实测结论 |
|---|---|---|
| `_text` 节尾 slack（`0x7BFA10`，RawSize>VirtualSize） | 全零 | 不可用——JO 运行时把 `_text` 节覆盖为数据表 |
| `.text` 末尾零填充（`0x794DEB` 起） | 全零 | 不可用——被游戏 JIT 生成的 thunk 覆盖（cc 填充 + b9/e9 特征，引用每次运行都变的堆地址） |
| `.text` 中部函数间 cc 间隙 `0x7472C9` | 55 × 0xCC | 可用——cc 填充不被引擎覆盖也不会被执行，JO 系列补丁（FP 灯光/载具 VTOL）均采用同类洞型实机验证稳定 |

**文件里的零字节 ≠ 运行时可用空间**；JO 可靠洞位只有 `.text` 中部 cc 间隙。

### 4.2 注入方案（每档写入 55 字节，与原版差异 54 字节）

**钩子**（文件 `0xEAA5A`，10 字节）——子弹重力块，天然"仅子弹"：

```
004eaa4e  TEST [EBX+0x114],0x100      ; 对象标志 bit 0x100
004eaa58  JNZ  0x4eaa64               ; 置位=手雷类：跳过 mover 重力
004eaa5a  ADD  [EBX+0xa0],0xffffff59  ; 清零=子弹：vz -= 167   ★钩子
004eaa64  PUSH 0 / PUSH 1 / PUSH EBX
004eaa69  CALL 0x4e5ec0               ; drag 函数（手雷的重力在其内部 0x4E6329）
```

```
原始: 81 83 A0 00 00 00 59 FF FF FF
替换: E8 6A C8 25 00 90 90 90 90 90   ; CALL 0x7472C9（rel32=0x25C86A）+ NOP×5
```

引擎把重力拆成互补两半：bit 0x100 **清零**（子弹）重力在 mover，**置位**（手雷/抛掷物）重力在 drag 函数内（`0x4E6329`）。钩在子弹分支，手雷走 JNZ 直接跳过补丁——无需任何额外判断。

**洞内**（文件 `0x3472C9`，45 字节）：

```
0x7472C9  add  [ebx+0xA0],-167         ; 原重力指令原样搬入
0x7472D3  mov  eax,[0x02C059E4]        ; wind_x
0x7472D8  shl  eax,2                   ; ×4 对齐 BHD 满风标度（见 4.3）
0x7472DB  sar  eax,K                   ; 档位
0x7472DE  add  [ebx+0x98],eax          ; vx += wind
0x7472E4  mov  eax,[0x02C059E8]        ; wind_y
0x7472E9  shl  eax,2
0x7472EC  sar  eax,K
0x7472EF  add  [ebx+0x9C],eax          ; vy += wind
0x7472F5  ret                          ; → 0x4EAA5F(NOP×5) → 0x4EAA64 压参 → CALL drag
```

语义：把风从死代码改为**每 tick 恒力加速度**（理想风模型，与 DFBHD 补丁同款），对 mover `FUN_004e9d70` 全部弹种生效、不依赖 drag≠1；`sar` 算术右移保证负风分量符号正确；wind_z 恒 0 无需处理 vz。寄存器安全：EBX=弹体实例（原指令即用），EAX 在钩子点为死值（`0x4EAA71` 重载）。

### 4.3 缩放档位调节

16.16 定点、tick≈60Hz：重力 167/帧 ≈ 9.17 m/s²；JO 满风 45kph ≈ 197/帧 ≈ **118% 重力**，BHD 满风 ≈ 736/帧 ≈ **441% 重力**。洞内先 `shl 2`（×4）使 JO 满风 ≈ 788/帧 ≈ 472% 重力，与 BHD 标度对齐（+7% 以内），**BHD 补丁的档位表原样复用**。

改文件偏移 **`0x3472DD`** 与 **`0x3472EE`**（`sar` 立即数，两处必须一致）：

| K | 风力（满风相对重力） | 300m 漂移* | 说明 |
|---|---|---|---|
| `00` | 472% | ~3.0 m | 仅参考 |
| `01` | 236% | ~1.5 m | |
| `02` | 118% | ~76 cm | = JO 原生满风力度 |
| `03` | 59% | ~38 cm | |
| `04` | 29.5% | ~19 cm | |
| `05` | 14.7% | ~9.5 cm | |
| **`06`** | 7.3% | ~4.8 cm | **推荐档** |
| **`07`** | 3.7% | ~2.4 cm | **推荐档** |
| `08` | 1.8% | ~1.2 cm | 极轻微 |

\* 锚点：800 m/s 子弹、45kph 满侧风、平方律漂移 ½at²。

### 4.4 覆盖范围与未覆盖项

- ✅ 子弹 mover `FUN_004e9d70` 的全部弹种——钩子位于 drag 调用前的公共路径，与 drag 取值无关。
- ✅ 手雷/炸药包/claymore 等抛掷物：走 bit 0x100 置位互补分支（重力在 drag 函数内 `0x4E6329`），自动不受补丁影响，无需处理。
- ❌ 士兵/载具 mover（其余 14 处重力站点，字节模式 `81 8r A0 00 00 00 59 FF FF FF` 全文件扫描共 16 处）：无需。
- 无风地图：风矢量为 0，补丁加法恒为 0，弹道与原版逐位一致，可常驻安装。

## 5. 实测记录

1. 实机验证：风偏生效，**方向正确**（`+=` 约定成立——存储风矢量指向下风向，与 BHD 补丁实测一致）。
2. 仅 MED 设置了风的地图受影响；无风地图无差异。
3. 补丁完整性：生成器五重断言（源文件尺寸 4,612,096；钩子原始字节逐位核对；洞区 55 字节全 0xCC；每档与原版 diff 恰 54 字节且全部落在钩子/洞范围内；九档互 diff 恰 2 字节 @ `0x3472DD`/`0x3472EE`）。断言链曾拦下两个真实 bug：rel32 手算错误（已改公式断言兜底）、第二条 `sar` 立即数索引错位（洞内偏移 37 而非对称想当然的 36——36 是操作码 F8）。
