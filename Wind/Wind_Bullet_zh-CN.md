# 《Delta Force: Black Hawk Down》风系统与子弹风偏补丁分析报告

- **目标文件**: `DFBHD_P.exe`（v1.5.0.5，32 位 PE，ImageBase `0x400000`，2,547,712 字节）
- **方法**: 纯静态分析（python + capstone + pefile）+ 游戏内实测验证
- **日期**: 2026-10-20
- **结论**: 引擎有完整的天气风系统（风速 kph、风向角度、风矢量全局），并且**风矢量已经接入了子弹阻力函数**，但默认弹种阻力系数恒为 1.0，导致该函数直接空转返回——子弹"不受风"是设计使然而非缺失。通过 5 字节入口跳转 + `_TEXT` 节洞注入 10 条指令，即可让所有普通弹道弹种获得真实的风偏。已实测生效。

---

## 1. 地址换算约定

`.text` 内 `VA = 文件偏移 + 0x400000`。补丁洞位于 `_TEXT` 节：VA `0x610010` = 文件偏移 `0x210010`（该节 RawSize 0x1000、VirtualSize 仅 0xC，尾部全零，flags `0xE0000020` = RWX）。

## 2. 风系统取证

### 2.1 天气主变量与生成路径

| 变量 | VA | 含义 |
|---|---|---|
| 风速 | `0x715798` | kph 整数（UI 显示，上限 45 在天气/存档侧钳制） |
| 风向 | `0x715794` | 角度 |
| 天气模式 | `0x9F214C` / `0x9F21DC` | 0=自定义、1=无风、2=随机风 |

天气更新代码（`0x4B9AA7` / `0x4B9F0B` / `0x4BA2DF` 等）读取风速/风向后 `call 0x5370E0`（setter）；模式 2 走 `call 0x5371D0`：`rand*360>>16` 生成方向、`rand>>11` 生成风速。

### 2.2 风矢量全局（核心）

| 变量 | VA | 含义 |
|---|---|---|
| wind_x | `0xE19DC0` | 16.16 定点 |
| wind_y | `0xE19DC4` | 16.16 定点 |
| wind_z | `0xE19DC8` | 恒 0 |
| 弱风副本 | `0xE19DCC` / `0xE19DD0` | wind_x/y 的一半 |

换算在 setter `0x5370E0`（文件 `0x1370E0`）内完成：`0x537177 call 0x55E6E0`（1024 段 sin/cos 插值表，表指针 `[0x654CF4]`，角度按 `>>22` 取段），随后 `0x537185: imul …; shrd eax,edx,22; mov [0xE19DC0],eax`，即 **wind = speed × trig(定点) >> 22**，方向由 cos/sin 分解进 x/y。

### 2.3 粒子侧（风"看起来只影响烟/尘"的原因）

- 粒子积分环 `0x536F90`（调用者 `0x4B4B8E`）：对 `0xE14DB4` 起、步长 `0x14` 的粒子数组**逐帧**执行 `[pos-4] += wind_x; [pos] += wind_y`（垂直项按天气类型取 -2048/-20480）。粒子按**全量风矢量**位移，所以烟、尘、火苗飘动明显。
- 视觉路径 `0x55C843`：读 `0xE19DC0/4/8` → `call 0x55D5D0`（fild 转 float，×1/65536）→ `fmul [0x611570]=62.0`。

## 3. 子弹侧：风为什么无效（根因）

子弹 mover `0x491B00` 每帧在 `0x492894` 调用阻力函数 `0x491930`（`push ebx; call`，ebx=弹体实例）。函数逻辑（0x491930–0x4919F4 已完整反汇编核实）：

```
0x491934  mov  ecx,[ebp+8]          ; ecx = 弹体实例
0x491937  mov  edx,[ecx+0x16c]      ; 弹种索引 → 查表 [0x683ee8]
0x49194D  mov  eax,[edx+eax*4+0x1c] ; drag = def+0x1C（16.16 定点）
0x491951  cmp  eax,0x10000          ; ★ 默认弹种 drag == 1.0
0x491959  je   0x491a2e             ; ★ 直接返回 —— 风贡献 = 0
0x49195F  mov  eax,[ecx+0x10]       ; Z 位置
0x491962  cmp  eax,[0xb63374]       ; 水面
0x49196E  ...                       ; v = (v + wind) → v = v*drag>>16 → v = v - wind
```

即引擎对风的设计是**相对介质阻力**：速度渐近风速，且仅在 `drag ≠ 1.0` 且飞行于水面以上时生效。所有默认弹种 `drag = 0x10000`，函数在 `0x491959` 空转返回——**子弹不受风的根因**。速度字段：实例 `+0x6C`=vx、`+0x70`=vy、`+0x74`=vz（重力只加 vz，见重力报告）。

## 4. 补丁设计

### 4.1 代码洞选择

`.text` 无 ≥48 字节空隙；`_TEXT` 节（VA `0x610000`，RawSize 0x1000，VirtualSize 仅 0xC，RWX）`0x610010` 起约 4KB 全零且可执行 → 理想洞位。

### 4.2 注入方案（共 39 字节改动）

**钩子**（文件 `0x91930`，5 字节）：

```
55 8B EC 51 8B  →  E9 DB E6 17 00      ; jmp 0x610010
```

**洞内**（文件 `0x210010`，34 字节）：

```
0x610010  push ebp / mov ebp,esp / push ecx / mov ecx,[ebp+8]   ; 重放被覆盖的序言
0x610017  mov  eax,[0xE19DC0]
0x61001C  sar  eax,5                    ; 风力缩放档（见 4.3）
0x61001F  add  [ecx+0x6C],eax           ; vx += wind_x >> 5
0x610022  mov  eax,[0xE19DC4]
0x610027  sar  eax,5
0x61002A  add  [ecx+0x70],eax           ; vy += wind_y >> 5
0x61002D  jmp  0x491937                 ; 回原流程（drag 判断等保持原样）
```

语义：把风从"渐近阻力"改为**每帧风力加速度**，对所有普通弹道弹种（含 `nogravity` 弹，因走 `0x492893` 公共路径）生效；不影响 drag≠1.0 弹种的原有介质逻辑（在其之前叠加）。

### 4.3 缩放档位调节

改文件偏移 **`0x21001D`** 与 **`0x210028`**（`sar` 立即数，两处必须一致）：

| 值 | 风力 | 说明 |
|---|---|---|
| `03` | /8 | 狂风，弹道明显弯曲 |
| `04` | /16 | 强 |
| **`05`** | /32 | 当前发布版（实测"明显"档） |
| `06` | /64 | 温和 |
| `09` | /512 | 首版实测"有但很弱" |

### 4.4 覆盖范围与未覆盖项

- ✅ 普通弹道 mover `0x491B00` 的全部弹种。
- ❌ `useownmove` 抛掷物（手雷/炸药包/claymore）走各自 mover（`[obj+0x224]`），不调用 `0x491930`；如需覆盖，按重力报告中 B 组 12 个站点逐函数补同类钩子。
- ❌ 士兵/尸体（无需）。

## 5. 实测记录

1. `sar 9` 版：出现可观察风偏，但很弱 → 证实钩子路径正确。
2. `sar 5` 版（×16）：风偏明显，符合"增强"预期。
3. 补丁完整性：全文件仅 39 字节差异，其余与原版逐字节一致；无自校验迹象。
