# DF:BHD 原版子弹运动机制分析报告

- 分析对象：`DFBHD_LAAM_base.exe`（与 v1.5.0.5 弹道代码逐字节一致，锚点通用）
- 方法：capstone 静态反汇编 + 字符串锚点 + SYSDUMP 交叉验证
- 日期：2026-10-21

---

## 1. 总览

子弹运动是一个**每帧欧拉积分的真空抛物线模型**：

```
每帧:  pos += v
        v.z += -167        (重力, 16.16 定点)
        v = (v+wind)*drag - wind   (仅 drag≠1.0 时)
        v.z 钳位 ≥ -16384
        地形/命中/killzone 检测
```

没有水平减速、没有风偏（默认弹种）、没有质量效应。所有"物理"都是硬编码立即数，与弹种数据无关。

数值表示：全程 **16.16 定点**（1.0 单位 = 65536），重力步长 `-167/65536 ≈ -0.00255 单位/帧`。

## 2. 数据结构：ammo def 记录（items.def，步长 1976 字节）

解析器位于 `0x4106xx`，关键字→字段映射（均已反汇编确认）：

| def 关键字 | 记录偏移 | 说明 |
|---|---|---|
| （标志位组） | `+0x00` | 含 `nogravity`=bit0x400、入水=bit0x100000 等 |
| `max_age` | `+0x08` | 存活帧数 |
| `arm_age` | `+0x0C` | 引信保险距离/时间 |
| `velocity` | `+0x18` | 初速（×方向向量写入实例 vx/vy/vz） |
| （drag） | `+0x1C` | 速度衰减系数，默认 `0x10000`=1.0 |
| `bullet_mass` | `+0x20` | **解析后无任何消费者——摆设字段** |
| `ai_launch` | `+0x50` | AI 发射行为 |
| `ai_launcheffect` | `+0x54` | AI 发射特效 |

关键字块整体位于 `0x61FBD8~0x620078`：`shotgun / noage / useownmove / ownerimmune / instantkillzone / hasitem / nogravity / nocollide / nosmoke / forcetracer / silenced / shrapnel / muzzle1 / muzzle2 / velocity / bullet_mass ...`

## 3. 逐帧 mover：`0x491B00`

### 3.1 位置积分
朴素欧拉：`pos += v`（每帧），v 存于实例 `+0x6C/70/74`。

### 3.2 重力块 `0x492866`

```
0x492866  mov  eax,[ebx+0xd8]     ; 标志
0x49286C  test ah,4               ; nogravity?
0x49286F  jne  0x492893           ; 是 → 跳过重力
0x492871  test eax,0x100000       ; 已入水?
0x492878  cmp  ecx,[0xb63374]     ; 水面高度
0x492880  add  [ebx+0x74], -20    ; 水下: 弱重力
0x492888  add  [ebx+0x74], -167   ; 空中: 标准重力
0x492893  ...                     ; 终端速度钳位 -16384
```

重力是**每帧常量**，与弹种质量、口径、速度全部无关。

### 3.3 阻力/风函数 `0x491930`（在 `0x492894` 被调用）

```
v = (v + wind) * drag - wind      ; 速度向风矢量渐近
```

- 入口先 `cmp [ecx+0x1C], 0x10000 / je ret`：**drag=1.0（所有默认弹种）时整个函数空转返回**——这就是原版"风只影响粒子、不影响子弹"的根因。
- 风矢量全局：`0xE19DC0/DC4/DC8`（x/y/z），由天气系统 `0x5370E0` 用风速(kph, `0x715798`)×sin/cos 表换算为 16.16 定点；z 恒 0。
- 只有特殊弹种（drag≠1.0，如火箭 `0x3E7F`）才真正"感受"到风。

### 3.4 mover 分发架构

`0x491CB8` 检查 def `useownmove` 标志 → 置位则改调 `[obj+0x224]` 的**自定义移动函数**。手雷/炸药包/claymore/士兵/车辆各有独立 mover，**重力常量在每个 mover 里重复硬编码**——全 exe 共 20 处（-167×13、-334×3、-55×3、-20×1 等），详见 Gravity 报告。

## 4. 物理本质

- 轨迹方程：`y(x) = (g/2v₀²)·x²`（g=167/65536/帧），标准抛物线；
- 水平速度永不衰减（drag=1 时无任何阻力项）；
- 质量不出现（F=ma 被约掉，所有子弹同一重力步长）；
- 无升力、无马格努斯、无科里奥利、无终端速度对水平的限制。

即：**引擎弹道 = 真空 + 恒定重力 + 可选介质阻力（默认关闭）**。

| | DF:BHD | JO |

| 速度字段 | +0x6C/70/74 | +0x98/9C/A0 |

## 6. 已验证的可改造点

| 目的 | 位置 | 手段 |
|---|---|---|
| 改重力 | 20 处 `add [inst+0x74], imm32` | 直接改立即数（文件偏移=VA-0x400000） |
| 全局无重力 | `0x49286F` `75→EB` | 强制 jmp |
| 子弹受风 | hook `0x491930` 入口 → 代码洞 `_TEXT` VA `0x610010`（4KB 零节，RWX） | 注入 `v += wind>>K`（理想）或 `v += (wind-v)>>K`（弛豫） |
| 质量生效 | 同上洞内读 `[ecx+0x20]` 参与重力缩放 | 需新增 imul/sar 数条 |

## 7. 结论

原版子弹运动是刻意简化的"可预测抛物线"：设计者用 drag 字段预留了介质/风接口但从未给默认弹种启用，`bullet_mass` 则是彻底的空洞字段。引擎所有物理都发生在**实例根位置级**（每帧定点积分），不存在骨骼/刚体求解器——这也是布娃娃无法由数据文件实现、而风偏/重力补丁只需替换一个立即数或挂一个 10 指令钩子的原因。
